# ระบบการ์ดมอนสเตอร์ใส่อุปกรณ์ (RO-style) — Draft v1 (2026-11-03)

> สถานะ: **LIVE v24** (คิวอนุมัติ 2026-11-03) · ข้อมูลการ์ดอยู่ที่ `game/src/data/cards.ts`
> โค้ดที่เกี่ยว: `data/meta.ts` (ITEMS, wornItems, heroStats), `save.ts`, `scenes/BattleScene.ts` (ตอนมอนตาย), `scenes/CharacterScene.ts` (หน้าอุปกรณ์)

## 0. TL;DR (so what)
- มอนทุกตัวมี **การ์ด 1 ใบ** (32 ใบ) ดรอปตอนฆ่า ได้แล้ว **เก็บถาวร** (แพ้ก็ได้เก็บ เหมือน zeny)
- อุปกรณ์มี **ช่องใส่การ์ด 0–2 ช่อง** ใส่/ถอดในเมือง **ฟรี การ์ดไม่แตก** (ไม่โหดแบบ RO)
- การ์ดใบนึงใส่ได้แค่ช่องชนิดเดียว: **อาวุธ / เกราะ / เครื่องประดับ** (เหมือน RO)
- ผลการ์ดใช้ **Stats ที่มีอยู่แล้ว** ทั้งหมด (`base` + `mod` แบบเดียวกับ items-v2) ไม่ต้องเขียน logic ต่อสู้ใหม่ในเฟส 1
- มี **Pity** กันดวงซวย: ฆ่าตัวเดิมครบ N ตัวแล้วยังไม่ได้ = ได้แน่
- ตัวเลือก 1-of-3 ระหว่างรอบ **เลิกเรียกว่า "การ์ด"** เพื่อไม่ให้ชนกับระบบนี้ (ชื่อใหม่รอคิวเลือก ดูข้อ 9)

## 1. ทำไมต้องมี
- ตอนนี้ของที่ได้ถาวรมีแค่ zeny / EXP / เพชร → ฟาร์มดันเก่าแล้ว "ไม่มีอะไรลุ้น"
- การ์ด = เหตุผลให้กลับไปตีดันเก่า + ให้ build แต่ละคลาสต่างกันได้อีกชั้น โดยไม่ต้องเพิ่มไอเทมใหม่เยอะ
- ไม่ขัดจุดยืน monetization: **ไม่มีกาชา ไม่มีขายการ์ด/ขายช่องด้วยเงินจริงหรือเพชร** หาได้จากการเล่นอย่างเดียว

## 2. อัตราดรอป
| ชนิดมอน | อัตราพื้นฐาน / การฆ่า | Pity (ได้แน่เมื่อฆ่าครบ) |
|---|---|---|
| มอนธรรมดา | 1.5% | 80 ตัว (ตัวเดิม) |
| มินิบอส D3 / บอสย่อย D4–5 | 8% | 12 ครั้ง |
| บอสประจำดัน (MVP) | 5% | 20 ครั้ง |

- LUK ช่วย: `cardRate = base × (1 + โบนัสดรอปจาก LUK เดิม)` ใช้สูตร `P.luk.dropPct / dropCap` ที่มีอยู่ (cap เดิม) → LUK เยอะดรอปได้ ~1.5 เท่า
- ของ/การ์ดที่มี `dropChance` (เช่น แหวนใบโคลเวอร์) **ไม่** คูณอัตราการ์ด (ใช้กับเพชรเหมือนเดิม) กันสายดวงพุ่งเกิน
- Pity นับต่อการ์ด เก็บใน save (`cardPity[cardId]`) ได้การ์ดแล้วรีเซ็ตเป็น 0
- มอนที่ถูกเรียกออกมา (เจลล็อปจิ๋ว, ลูกแมงมุม, เศษกระจก) **ไม่มีการ์ด** กันฟาร์มลูกสมุน
- ประมาณการ: รอบ D1 ฆ่า ~25–30 ตัว → ได้การ์ดธรรมดา ~0.4 ใบ/รอบ, บอส D1 ได้แน่ภายใน 20 เคลียร์
- ตอนดรอป: ตัวอักษรลอย `🃏 การ์ดหมาป่าสีเทา!` + เสียงพิเศษ, หน้าสรุปผลมีบรรทัด "การ์ดที่ได้"

## 3. ช่องใส่การ์ด (slots)
เพิ่มฟิลด์ `slots?: number` ใน `Item` (ไม่ใส่ = ใช้กฎด้านล่าง) · RO ใช้ 0–4 ช่อง หนูลดเหลือ 0–2 ให้อ่านง่าย

| ไอเทม | ช่อง |
|---|---|
| ของเริ่มต้น (มีดโนวิส, เสื้อผ้าฝ้าย, ว่าง) | 0 |
| อาวุธ/เกราะร้านพื้นฐาน (ดาบสั้น ... เกราะโซ่) | 1 |
| ของคลาส 2 สาย (520–560z) + เกราะคลาส | 1 |
| อาวุธดัน 2 (1100z) | **2** |
| เครื่องประดับทุกชิ้น | 1 |
| เครื่องประดับเตรียมดัน 4–5 (เครื่องรางล้างพิษ, หัวใจไฮดรา) | 1 |

- รวมสูงสุดตอนนี้ = อาวุธ 2 + เกราะ 1 + ประดับ 1 = **4 ใบ**
- ใส่การ์ดซ้ำใบเดียวกันได้ (เช่น ใส่ 2 ใบในอาวุธ) ค่าบวกกัน แต่ cap เดิมของ items-v2 ยังทำงาน (ดูดเลือด 40%, คริ ฯลฯ)
- ใส่ของผิดอาชีพค้างไว้ = ทั้งไอเทม **และการ์ดในนั้น** ไม่ได้ค่าพลัง (ตามกฎ `wornItems` เดิม)

## 4. ใส่ / ถอด / การ์ดซ้ำ
- ใส่/ถอดได้ในเมืองเท่านั้น (หน้าตัวละคร → แท็บ 🃏 การ์ด → กด "ใส่" ที่การ์ด = ใส่ช่องว่างของชิ้นที่ใส่อยู่ · กดการ์ดในช่อง = ถอด) ระหว่างรอบเปลี่ยนไม่ได้
- **ถอดฟรี การ์ดกลับเข้ากระเป๋า** ทั้งการ์ดและไอเทมไม่หาย (RO จริงต้องเลือกเสียอย่างใดอย่างหนึ่ง แต่เกมเราไม่มีระบบเทรด โหดไปเปล่าๆ ค่ะ)
- การ์ดซ้ำ: เก็บเป็นจำนวน (`cards[cardId] = n`) ใส่หลายชิ้นได้ตามจำนวนที่มี · ขายได้ในแท็บการ์ด (ธรรมดา 30z, มินิ 150z, บอส 300z)
- **สมุดการ์ด** (แท็บใหม่): โชว์ทุกใบ ใบที่ยังไม่เจอเป็นเงา `?` + บอกว่าดรอปจากดันไหน → ให้มีเป้าหมายเก็บสะสม (โบนัสเก็บครบ = เฟส 2)

## 5. หลักการตั้งค่าพลังการ์ด
- การ์ดธรรมดา ≈ **1/3 ของไอเทมระดับเดียวกัน** (ไอเทมคลาส 520z ให้ ~ATK 8 + ดูดเลือด 6%) → การ์ดให้ ค่าหลัก 1 อย่าง เช่น ATK +4, คริ +3%, HP +40
- การ์ดมินิ/บอส = แรงกว่าชัดเจน **แต่มีข้อเสียแบบ RO** (เช่น แรงขึ้นแต่ Flee ลด) ให้ต้องคิดก่อนใส่ ไม่ใช่ใส่แล้วจบ
- การ์ดดันลึกแรงขึ้นตาม tier แต่ไม่เกิน ~1.6 เท่าของดัน 1 (กันของเก่าไร้ค่า)
- ค่าพลังการ์ด**ไม่ขึ้นกับคลาส** ใครได้ก็ใส่ได้ ช่องจำกัดผู้เล่นเอง (สายเวทคงไม่ใส่ ATK)
- **คริยังใช้กฎ RO**: แหล่งคริ = LUK, ไอเทม, tree, talent, ตัวเลือกระหว่างรอบ → การ์ดก็เป็น "ไอเทม" จึงให้คริได้ (`crit` กายภาพ / `spellCrit` เวท) ฮีลยังไม่คริเหมือนเดิม

## 7. เข้ากับระบบเดิมยังไง (implementation plan)
1. **`data/cards.ts` (ใหม่)**: `EquipCard { id, monster, slot: Slot, tier: 'normal'|'mini'|'boss', name, icon, base?, mod, pct? }` + `CARD_RULES` (อัตรา, pity, ราคาขาย) · คำอธิบายสร้างอัตโนมัติจาก `itemStatLine` เดิม (พิมพ์ไม่ตรงไม่ได้)
2. **`Item.slots?`** + ฟังก์ชัน `slotCount(it)` ตามตารางข้อ 3 (ไม่แก้ item id เดิม = save ไม่พัง)
3. **`SaveData`** เพิ่ม field optional (save เก่าเปิดได้):
   - `cards?: Record<string, number>` การ์ดในกระเป๋า (ยังไม่ได้ใส่)
   - `sockets?: Record<itemId, string[]>` การ์ดที่ใส่ในไอเทมแต่ละชิ้น (owned เป็น id ไม่ซ้ำอยู่แล้ว เก็บต่อ id ได้เลย)
   - `cardPity?: Record<string, number>`, `cardSeen?: string[]` (สมุดการ์ด)
4. **`heroStats`**: ตอนรวม `wornItems` ให้รวม `base`/`mod` ของการ์ดใน `sockets[item.id]` ด้วย (`gearBase` ด้วย เพื่อให้ STR/AGI จากการ์ดวิ่งผ่าน stat spec) แล้วค่อยคูณ `%` ท้ายสุด ก่อนใช้ cap
5. **`BattleScene` ตอนมอนตาย** (จุดเดียวกับ `dropChance` บรรทัด ~835): ทอยการ์ด → `runCards[]` → `settle()` บวกเข้า save ทั้งชนะ/แพ้
6. **UI**: CharacterScene แท็บอุปกรณ์มีช่อง `[🃏][ ]` ใต้ไอเทมที่ใส่อยู่ + แท็บใหม่ "สมุดการ์ด" · ไอเทมในร้านโชว์ `ช่องการ์ด N` · ขายไอเทม = การ์ดในนั้นกลับเข้ากระเป๋าก่อน
7. **Bot** (`tools/bot.cjs`): env `CARDS=best` ใส่การ์ดแนะนำต่อคลาส เช็กว่า D4/D5 win rate ไม่พุ่งเกิน (เป้า: การ์ดเต็มช่อง ช่วย +1–2 จาก 8 รอบ ไม่ใช่เปลี่ยนแพ้เป็นชนะหมด) และเช็กโจร D4/D5 ด้วย
8. Release: build → publish artifact + commit/push `main` (กฎ v22)

## 8. ไม่ทำในเฟส 1 (กัน overengineer)
- เผ่า/ธาตุ/ขนาดของมอน แบบ RO (เช่น "+20% vs สัตว์") → ต้องติด tag ให้มอนทุกตัวก่อน ไว้เฟส 2
- การ์ดที่มีเอฟเฟกต์พิเศษ (ตีแล้วร่ายสกิล, autospell) → เฟส 2
- โบนัสเก็บครบเซ็ต/ครบสมุด, การ์ดใส่หมวก/รองเท้า (ยังไม่มีช่องนั้น)
- อัปเกรด/ตีบวกไอเทม (refine) แยกเป็นงานอื่น

## 9. ชื่อใหม่ของตัวเลือก 1-of-3 ระหว่างรอบ (รอคิวเลือก)
